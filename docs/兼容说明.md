# 兼容性说明

**一句话**：screen-sense 是「只读」的，不抢屏幕、不抢键鼠、不抢端口，可以和绝大多数插件同时装。

---

## 一、会不会和截屏类插件打架

**不会，两者不冲突。**

| | 截屏类插件 | screen-sense |
|---|---|---|
| 拿什么 | 像素 | 结构化文本 |
| 系统调用 | `CopyFromScreen` / DXGI | UI Automation 读属性 |
| 是否独占 | 否 | 否 |
| 同时运行 | ✅ 可以 | ✅ 可以 |

两者是**互补**关系：

- 「我现在在哪个窗口、点了哪个按钮」→ 问我们，几十 token
- 「这个页面长什么样、图里写了什么」→ 问截屏插件，一千多 token

**唯一要避免的浪费**：如果两个插件都开了截图，同一块屏会被截两次。建议**只让一个插件负责像素**，另一个用文本。

---

## 二、端口

- 默认 **8791**
- 被占用会自动往后试 8792…8800，**最多试 10 个**
- 实际端口写进同目录的 `port.txt`
- 客户端（`query.py`、`install.ps1`）会自动读 `port.txt`，不需要手动改

> 如果你有别的服务也在 8791，我们不会去抢，会自己挪窝。

---

## 三、系统层面做了什么、没做什么

**只读的部分**

- 读窗口标题、类名、前台窗口句柄
- 读 UI Automation 树里的**焦点控件**（角色、名称、值、位置）
- 读顶层窗口列表

**不做的事**

- ❌ 不装全局键盘 / 鼠标钩子
- ❌ 不接管输入、不模拟点击（`act` 系列留给了集成版，这个插件没有）
- ❌ 不读剪贴板
- ❌ 不改系统设置、不写注册表
- ❌ 不联网上传任何东西（除非你自己发截图给模型）

**会写盘的只有一处**：`captures/` 下的截图，只留最近 20 张，`{"op":"captures","keep":-1}` 一键清空。

## 四、和其他工具同装时的注意事项

| 场景 | 影响 | 建议 |
|---|---|---|
| 同时装另一个 UIA 工具 | 会有两份 UIA 调用，略增 CPU | 两者轮询间隔都 ≥250ms 时，实测影响可忽略 |
| 同时装截屏工具 | 功能重叠但不冲突 | 只留一个负责像素 |
| 打游戏的场景 | UIA 读不到全屏游戏 | 自动退化为「只有 app 名」，或显式要求截图 |
| 以管理员运行的程序 | 读不到其窗口内容 | 需要同权限运行，属 Windows 限制 |
| 沙箱环境（如 DSH 沙箱） | UIA 会被安全策略拦 | 插件需在普通权限下运行 |

## 五、资源占用（本机实测）

| 项 | 数值 |
|---|---|
| 常驻内存 | 约 40–60 MB（PowerShell 进程） |
| CPU | 轮询 250ms，空闲时 <1% |
| 单次摘要 | 10–40 ms |
| 单次截图（L2） | 150–200 ms |
