## 一、要不要登记软件著作权

**结论：不登记也能发，但建议登记，成本很低。**

### 事实

- 著作权 **自作品完成之日起自动产生**，不需要登记就能主张权利。
- 登记的唯一好处是：**举证更容易**。发生纠纷时，登记证书是初步证据，比翻聊天记录、翻云盘时间戳靠谱得多。
- 中国软件著作权登记在 **中国版权保护中心**（<https://www.ccopyright.com.cn>）线上办理：
  - 官方登记费 **已取消**（免费）；找代理机构一般收几百元服务费。
  - 常规周期约 **30–60 个工作日**；加急要额外付费。
  - 材料：申请表、身份证明、**源代码前后各 30 页（共 60 页，不足 60 页全交）**、软件说明书 / 用户手册。
- AI 辅助开发的软件**可以登记**，登记人写自然人（或法人）。材料里如实说明「使用 AI 辅助编程」即可，不必回避——目前登记不审查这一项，但虚假陈述有风险。

### 建议

1. 先把版本稳定在 0.1.x，再登记，避免版本变动又要补登记。
2. 登记名称建议：**「screen-sense 屏幕感知软件 V1.0」**（软件全称 + 版本号）。
3. 源程序提交前打成一个 PDF，页眉写上软件名称和版本号。
4. 顺便把 README、CHANGELOG 存一份当"开发文档"的佐证。

## 二、开源许可

本仓库用 **MIT**（见 `LICENSE`）。理由：

- 最宽松、最容易被接受，别人拿去用不会担心法律风险
- 保留版权声明即可，我们的名字会跟着代码走
- 如果担心被拿去闭源卖，可以换 **Apache-2.0**（带专利授权条款）或 **AGPL-3.0**（衍生必须开源）

**注意**：MIT 一旦发布就撤不回。想保留商业授权空间的话，可以考虑「双许可」（开源 MIT + 商业授权），但要一开始就设计好。

## 三、发到哪里

| 渠道 | 用途 | 备注 |
|---|---|---|
| **GitHub Releases** | 主发布地 | 打 tag、传 zip、附 sha256 |
| **Gitee** | 国内镜像 | 同步推送，墙内访问快 |
| **蓝奏云 / 网盘** | 给人下载 zip | 只放安装包，不放源码 |
| **B站专栏 + 视频** | 介绍和演示 | 演示「省 12 倍 token」最直观 |
| **DSH 技能目录** | 直接可用 | `SKILL.md` 放 `~/.dsh/skills/dsh-screen-sense/` |

## 四、发布前检查清单

- [ ] `LICENSE` 存在且年份/署名正确
- [ ] `README.md` 有：一句话定位、实测数据、安装命令、限制
- [ ] `CHANGELOG.md` 写了这一版改了什么
- [ ] 版本号在 README / CHANGELOG / 代码里一致
- [ ] 没有第三方素材（图片、字体、模型）混进来
- [ ] 没有密钥、内网地址、个人路径
- [ ] `tests/` 全部通过
- [ ] 隐私声明写清楚：不截屏（除非明确要求）、不落盘、密码框屏蔽
- [ ] 打 zip 后算 sha256，写进 Release 说明

## 五、打一个发布包

```powershell
# 在仓库根目录
$ver = "0.1.0"
$zip = "screen-sense-$ver.zip"
Compress-Archive -Path .\screen-sense\* -DestinationPath $zip -Force
Get-FileHash $zip -Algorithm SHA256
```

Release 说明模板：

```
## screen-sense v0.1.0

不截屏的屏幕感知。单次摘要 25ms / 约 130 token，截图方案的 1/12。

- 密码框 / 密码管理器屏蔽

SHA256: <粘贴>
```
